# 研究方法与证据边界

## 1. 研究目的

本阶段回答五个问题：

1. 目标用户是否足够具体，且问题是否真实存在；
2. 市面方案解决了哪些环节，留下了哪些空白；
3. 如何触达老人和家属并完成最小验证；
4. 哪些范围、风险和合规问题必须主动排除；
5. 48 小时原型与后续真实产品分别怎样实现。

## 2. 证据分级

| 等级 | 定义 | 可以支持什么 | 不能支持什么 |
|---|---|---|---|
| A | 法律法规、政府统计、政府政策、正式标准 | 人口、政策、合规底线、行业方向 | 单一产品的真实易用性 |
| B | 厂商官网、官方帮助、官方隐私政策 | 已公开功能、权限和平台限制 | 用户是否真正喜欢或能独立使用 |
| C | 候选人本人实际操作记录 | 操作路径、可用性问题、界面观察 | 普遍人群结论 |
| D | 产品分析与推演 | 假设、实验方案、设计方向 | 真实用户事实或实测结果 |

所有结论必须能够追溯到 A/B/C 中至少一种证据，或明确标为 D 级假设。

## 3. 当前研究方法

- 桌面研究：人口、互联网使用、政策、法律、行业发展和厂商公开能力。
- 竞品功能拆解：提醒、家庭共享、语音入口、远程守护、权限撤回和失败反馈。
- 场景推演：用预设角色验证状态是否完整，不冒充真人访谈。
- 原型走查：按验收脚本执行主流程、修改/取消流程和失败流程。

## 4. 重要限制

当前资料不包含真人访谈，也不包含候选人本人对两个产品的实际操作证据。根据考核要求，提交前必须由候选人本人实际体验至少两个产品或替代方案，并补充：

- 体验日期、设备和版本；
- 从入口到完成任务的逐步记录；
- 关键截图或屏幕录制索引；
- 观察事实与个人判断分开书写；
- 该体验具体改变了本方案的哪一项设计。

建议优先体验：

1. 一个通用家庭协作/提醒工具；
2. 一个具有长辈模式、语音入口或远程守护能力的产品。

AI 不能替代这一步，也不能生成虚构的“老人反馈”“访谈原话”或“实测数据”。

```md
- 我的解释：
- 对本方案的影响：
```

## 6. 研究完成标准

- 每个市场数字和法律判断均有来源；
- 每个产品能力均来自厂商公开资料或本人体验；
- 不把桌面研究写成真实体验；
- 不把模拟角色写成真实用户；
- 不把预期指标写成实测结果；
- 已列出与结论相反的可能性和验证方法。
