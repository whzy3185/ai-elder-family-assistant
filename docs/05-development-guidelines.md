# 开发准则

## 1. 产品开发原则

1. **老人拥有最终决定权**：创建、分享、修改和取消均由老人确认。
2. **一次只解决一件事**：本版本不扩展为综合养老平台。
3. **AI 建议不等于执行**：AI 只生成待确认的结构化结果。
4. **真实状态优先于乐观体验**：未送达、未查看、未回应必须区分。
5. **失败可继续**：语音、AI 或消息失败时提供手动路径。
6. **最小共享**：只向指定家属共享本次事务必要字段。
7. **演示与生产边界明确**：模拟数据和演示控制必须显式标注。

## 2. 目标演示规格

- 形态：移动端优先的响应式 Web 原型；
- 主要画布：390 × 844 CSS px；
- 家属端可复用相同画布；
- 桌面浏览器以手机框或响应式窄栏演示；
- 原型数据全部为虚构预置数据；
- 不需要联网、不调用真实 AI、不发送真实消息。

## 3. 适老交互基线

W3C WCAG 2.2 要求普通文本对比度至少 4.5:1、大文本至少 3:1，并支持文本放大至 200% 而不丢失功能；本项目以 WCAG AA 为最低参考，同时采用更保守的触控和文案标准。[来源](https://www.w3.org/TR/wcag/)

### 视觉

- 老人端正文默认 20 px，关键结果 24—28 px；家属端正文不低于 16 px；
- 普通文本对比度不低于 4.5:1，关键文本优先达到 7:1；
- 交互控件建议至少 48 × 48 CSS px，控件间保留清楚间距；
- 不只用颜色表达状态，同时使用文字和图标；
- 支持浏览器 200% 放大，不截断主流程。

### 信息与文案

- 一屏只有一个视觉主操作；
- 采用“请女儿陪我去”而不是“创建协作请求”；
- 结果句式包含“发生了什么 + 当前状态 + 下一步”；
- 禁止使用“很简单”“你又弄错了”等贬低或催促措辞；
- 时间同时显示相对和绝对信息，例如“明天 10:00（10 月 6 日）”；
- 关键对象显示称呼和头像/首字，避免只显示账号。

### 操作

- 语音不是唯一入口；
- 识别结果按事项、日期、时间、地点和协作对象分项确认；
- 返回不丢失已输入内容；
- 取消、撤回和删除需要解释后果并提供短时撤销；
- 操作后立即给出视觉反馈；
- 焦点顺序、键盘操作和屏幕阅读语义可用。

工信部适老化行动强调改善与政务、社区、社交、购物和金融等日常生活密切相关应用的可用性；国务院方案也提出大屏幕、大字体、大音量和操作简单等终端方向。[来源一](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2020/art_18a8b1029f724afc8b31264fcd0f4106.html) [来源二](https://www.miit.gov.cn/xwdt/szyw/art/2020/art_4bacc01b812e49c7b89d88373638bbf6.html)

## 4. 状态机准则

### 事务状态

```text
DRAFT
  -> UNDERSTANDING
  -> NEEDS_CONFIRMATION
  -> CONFIRMED
  -> COMPLETED
  -> CANCELLED
```

### 协作请求状态

```text
NOT_REQUESTED
  -> CONSENT_REQUIRED
  -> SENDING
  -> DELIVERED
  -> VIEWED
  -> ACCEPTED | DECLINED | CHANGE_PROPOSED | EXPIRED
  -> CANCELLED
```

规则：

- 事务和协作请求是两个对象，不能用一个布尔值代替；
- `SENDING` 不得显示为“已通知”；
- 老人取消事务后，未终结的协作请求必须进入 `CANCELLED`；
- 家属对已取消或过期请求的操作返回明确错误；
- 家属建议改期只创建提案，老人确认后才更新事务；
- 每次状态变化记录角色、时间和原因。

## 5. 前端工程准则

- TypeScript 开启严格模式；
- 业务状态集中在有限状态机或明确 reducer 中，禁止分散布尔变量；
- 展示组件不直接决定权限；
- 模拟服务使用与未来 API 相同的接口契约；
- 所有预置数据集中维护，禁止页面内复制不一致文案；
- 关键页面提供稳定路由或演示入口；
- 导航中出现的功能必须可进入完整画面；
- 禁止真实个人数据进入 fixture、截图和测试。

## 6. 测试准则

至少自动或手工验证：

1. 正常主流程；
2. 语音/理解错误后修改；
3. 老人取消；
4. 家属拒绝；
5. 家属建议改期、老人接受或拒绝；
6. 家属未回应/请求过期；
7. 模拟发送失败并重试；
8. 双端状态一致；
9. 200% 缩放和键盘操作；
10. 无网络、无密钥时 Docker 仍可完成全部演示。

## 7. Definition of Done

一个页面或状态只有同时满足以下条件才算完成：

- 在页面与状态清单中有唯一编号；
- 有明确进入方式、主要操作和去向；
- Web 原型中可实际进入；
- 静态原型中可独立查看；
- 文案、示例数据和状态与其他角色一致；
- 包含必要的失败、取消或返回行为；
- 无未实现的可点击入口；
- 通过适老和安全检查；
- README 或演示说明写明触发方法。
