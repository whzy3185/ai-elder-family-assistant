# 用户触达与验证方法

## 1. 双边用户定义

### 老人端目标用户

- 65—75 岁，独居或日间独处；
- 会接打电话、使用微信和扫码，但不熟悉复杂表单；
- 使用智能手机，可能有视力、听力或触控精度下降；
- 能对事务作出自主决定，不以认知障碍照护为本项目范围。

### 家属端目标用户

- 与老人分居但能在同城提供有限协助；
- 平日工作忙，不能持续查看老人状态；
- 希望收到具体、可回应的请求，而不是开放式监控。

### 必须区分的诉求

| 老人 | 家属 |
|---|---|
| 被听懂、少操作、结果明确 | 请求信息具体、响应成本可预期 |
| 自己决定是否共享 | 只在必要时收到通知 |
| 能撤回、修改和拒绝 | 不承担系统未明确说明的无限责任 |
| 不被持续监控 | 能知道老人是否已看到回应 |

## 2. 触达原则

**[分析]** 老人端的“下载”不是有效触达终点，首次成功事务才是。触达必须同时解决信任、安装、关系建立和第一次使用。

## 3. 渠道优先级

| 优先级 | 渠道 | 触达方式 | 优点 | 风险/成本 |
|---|---|---|---|---|
| P0 | 家属邀请 | 家属生成二维码或当面协助建立关系 | 信任高，双端同时触达 | 易变成家属主导，需老人明确同意 |
| P0 | 社区服务中心/居委会 | 现场演示一次真实日常事务 | 可提供面对面教育 | 合作周期长，需培训和物料 |
| P1 | 老年大学/社区课程 | 数字生活课程中的任务练习 | 适合观察真实困难 | 样本偏向主动学习者 |
| P1 | 手机厂商/运营商门店 | 新机或套餐服务中的适老引导 | 有设备入口和服务人员 | 渠道合作成本高、平台依赖 |
| P2 | 银行、药店、生活服务网点 | 非医疗场景的数字助老活动 | 老人高频线下场所 | 容易被误认为金融或医疗服务 |
| P2 | 微信内容/家庭群 | 家属教育内容和邀请链接 | 传播成本低 | 纯线上转化和信任较弱 |

国务院文件提出“子女线上下单、老人线下体验”等组合方式，为“家属线上发起 + 老人线下或当面完成首次使用”提供了政策层面的场景依据，但具体渠道效果仍需试点验证。[来源](https://app.www.gov.cn/govdata/gov/202401/15/511180/article.html)

## 4. 最小触达漏斗

1. **看到**：老人或家属理解产品只解决什么问题；
2. **同意**：老人理解将与谁共享哪些内容；
3. **建立关系**：双方确认，不默认开放持续权限；
4. **完成首件事务**：从表达需求到得到结果；
5. **复用**：在 14 天内主动创建第二件事务；
6. **推荐**：愿意向另一位家庭成员说明用途。

每一步分别记录人数，不能只统计安装量。

## 5. 最小验证设计

### 研究问题

1. 老人能否理解“系统听懂了什么”；
2. 老人能否独立纠正一个时间或地点错误；
3. 老人是否理解本次共享范围；
4. 家属能否在 30 秒内理解请求并作出回应；
5. 未回应或取消时，双方是否知道下一步。

### 样本建议

- 5 位符合目标条件的老人；
- 每位老人对应 1 位真实家属；
- 至少包含 2 种不同智能手机熟练度；
- 不把便利样本结果外推为市场结论。

### 方法

- 先观察，不在第一步解释按钮；
- 要求参与者复述当前状态和下一步；
- 记录求助点、误触、返回、重复阅读和放弃；
- 不采集真实身份证、病史、精确位置或账户信息；
- 使用虚构事务数据完成测试。

## 6. 指标口径

### 核心成功指标

`端到端协作成功率 = 无外部操作指导且得到明确协作结果的测试任务数 / 发起的有效测试任务数`

观察周期：单次可用性测试；后续试点可按周汇总。

### 过程指标

- 理解纠正成功率：发现并正确修正预设识别错误的人数 / 遇到错误的人数；
- 共享知情率：能正确复述共享字段的人数 / 发出协作请求的人数；
- 家属有效回应时长：请求送达至接受、拒绝或建议改期的中位时间；
- 状态误判率：错误认为“已发送”“已接受”或“已取消”的次数 / 全部关键状态判断次数。

这些都是定义和目标口径，不是实测结果。
