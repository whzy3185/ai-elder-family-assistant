# 风险与主动排除

## 1. 产品雷点

| 风险 | 典型错误 | 后果 | 本项目措施 |
|---|---|---|---|
| 把老人同质化 | “老人都不会用手机” | 用户画像失真 | 明确设备能力、居住与家庭条件 |
| 家属越权 | 默认查看位置、历史和全部日程 | 侵犯自主与隐私 | 单次最小共享；老人最终确认 |
| AI 直接执行 | 识别后自动发送或改期 | 错误行动且难追责 | 执行前结构化确认；可撤回 |
| 假成功 | 消息未送达仍显示已通知 | 老人错误依赖 | 区分处理中、送达、已查看和已回应 |
| 只有主流程 | 无拒绝、取消、超时和重试 | 演示断裂，真实不可用 | 显式状态机和双端状态映射 |
| 适老等于大字 | 文案复杂、操作层级深 | 仍不能独立完成 | 一屏一主任务、清楚反馈、替代输入 |
| 儿童化表达 | 使用哄劝语气或过度卡通 | 损害尊严与信任 | 使用成人、直接、尊重的文案 |
| 过度通知 | 反复催促家属或老人 | 打扰、焦虑、卸载 | 通知频率上限和用户控制 |

## 2. 伦理与隐私雷点

- 不以“安全”为由默认采集精确位置、通讯录、病史、声纹或持续环境音。
- 不允许家属秘密建立关系；首次绑定必须在老人端清楚确认。
- 不使用模糊同意把一次协作扩展为永久共享。
- 老人撤回同意后，不以拒绝服务作为惩罚；必要数据除外时需单独解释。
- 不把家属的便利置于老人意愿之上。
- 不将“未回应”解释为“拒绝”，也不把沉默解释为同意。
- 不展示真实家庭数据、令牌或原始语音于演示、截图或日志。

《个人信息保护法》要求个人信息处理具有明确、合理目的并采取影响最小的方式；敏感个人信息需要特定目的、充分必要性和严格保护，处理时通常需单独同意。[来源](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 3. 业务边界

本阶段主动排除：

- 医疗诊断、用药建议、病情判断；
- 110/120 等应急救援承诺；
- 跌倒检测、持续定位和摄像头监控；
- 支付、代购资金、银行卡和保险；
- 真实短信、电话、推送或微信接口；
- 智能家居控制；
- 开放式陪聊和情绪治疗；
- 养老机构运营后台；
- 任意输入的通用大模型能力。

排除理由：这些能力会显著提高安全责任、合规要求、外部依赖和异常处理成本，并偏离“一次日常事务协作”的考核重点。

## 4. AI 风险与控制

| 风险 | 控制 |
|---|---|
| 时间、地点、对象识别错误 | 分字段展示；未确认不执行 |
| 编造地点或流程 | 只整理用户输入；不生成专业建议 |
| 失败或超时 | 保留输入，切换手动表单 |
| 输出不可信 | 标注“请确认”，不使用权威口吻 |
| 上下文串用 | 每件事务独立；默认不读取历史 |
| 隐私泄漏 | 原型只用虚构数据；真实产品数据最小化 |

## 5. 渠道与运营雷点

- 不用“监护”“防失联”等恐惧话术强迫购买；
- 不让社区工作人员代替老人勾选隐私同意；
- 不把一次线下教学当作持续使用证据；
- 不以下载量或关系绑定量代替成功事务；
- 不承诺家属一定及时回应；
- 不把渠道方变成默认数据接收者。

## 6. 技术与交付雷点

- 前端包中出现真实 API 密钥、访问令牌或隐藏管理员入口；
- 只用 CSS 隐藏调试按钮，实际代码和路由仍可访问；
- 用不可预测 ID 代替服务端授权检查；
- 生产环境公开 Swagger、GraphQL introspection、source map 或堆栈；
- Docker 启动依赖私人账号、云服务或本地绝对路径；
- 静态图、Web 原型和产品文档状态不一致；
- 页面存在不可进入的导航和空按钮。

## 7. 停止或降级条件

出现以下任一情况，相关能力不得进入真实试点：

- 无法证明老人已知情同意共享；
- 无法在对象级和字段级限制家属访问；
- 消息送达状态无法区分；
- AI 输出可能触发医疗、支付或应急行动；
- 无法删除或撤回关系与共享；
- 安全测试发现跨家庭读取或修改数据；
- 无人工或非 AI 的任务完成路径。
