# 相关产品与替代方案

> 本文是基于厂商官方资料的桌面研究，不等同于候选人本人实际体验。提交前应按 [研究方法](00-research-method.md) 补充至少两个 C 级体验记录。

## 1. 样本对比

| 样本 | 已公开能力 | 可借鉴 | 不直接照搬 |
|---|---|---|---|
| Apple 提醒事项/日历 | Siri 创建提醒、共享日历、共享列表和任务分配 | 事务结构化、跨设备同步、协作对象清晰 | 功能密度高；不以老人理解和家属未回应为中心 |
| Google 家庭日历 | 家庭组自动获得共享日历，成员可创建和修改事件 | 家庭事件共享简单、跨设备 | 默认多人可编辑，权限粒度不适合“老人拥有最终决定权” |
| 支付宝长辈模式/蓝马甲 | 长辈模式；线下数字助老与防骗教育 | 大平台适老入口与线下教育结合 | 不是围绕一次家庭事务的双端闭环 |
| 华为远程守护长辈 | 扫码申请、长辈同意、位置与防诈提醒、可取消守护 | 建立关系需要双边确认；有取消关系能力 | 位置和设备守护权限较重，本项目不应默认申请 |
| 华为关怀模式 | 放大显示、简易布局、触感反馈、诈骗拦截 | 适老不只字体，还包括反馈和安全 | 系统级能力无法直接复制到 Web 原型 |
| 小米小爱 | 语音提醒、家庭传声、多设备入口 | 语音是低门槛输入，家庭广播可降低沟通成本 | 依赖特定硬件生态；广播不等于请求被明确接受 |
| 小度智能屏/智慧养老方案 | 语音、视频通话、家庭免接听等能力 | 智能屏适合固定居家场景 | 免接听和持续感知涉及高隐私风险，不纳入本项目 |
| Amazon Alexa | 语音呼叫、消息、指定紧急联系人；官方明确部分能力不替代紧急服务 | 必须清晰告知能力边界、网络失败和联系人失效 | 地区、语言、订阅和硬件依赖强；不作为中国市场直接方案 |

## 2. 官方资料观察

### Apple

Apple 官方资料说明，提醒事项支持通过 Siri 快速创建提醒；日历支持邀请与共享；相关指南还列出分配共享提醒事项。其优势是任务与系统生态结合，弱点是并未针对老人—家属协作中的授权、拒绝和未回应设计专门叙事。

来源：[Apple 打造的 App](https://www.apple.com.cn/apps/)、[Mac 员工入门指南](https://www.apple.com.cn/business/docs/resources/Mac_Employee_Starter_Guide.pdf)

### Google 家庭日历

Google 官方帮助显示，家庭组成员可以创建和修改家庭日历事件，也可以管理共享方式。它证明共享日历是成熟替代方案，同时暴露本项目的机会：对单次事务采用更小的共享范围和更清晰的最终确认权。

来源：[Use a family calendar on Google](https://support.google.com/families/answer/7157782?co=GENIE.Platform%3DDesktop&hl=en-uk)

### 支付宝

蚂蚁集团公开时间线显示，支付宝在 2021 年全量上线长辈模式，并通过“蓝马甲”开展数字助老和防骗教育。这说明适老产品的采用不仅是 UI 问题，也需要线下教育和可信入口。

来源：[蚂蚁集团发展历程](https://www.antgroup.com/hk/about)

### 华为

华为远程守护采用“发起申请—长辈同意—建立关系”的双边流程，并允许取消守护；关怀模式提供放大、简易布局、触感和安全能力。其权限能力较重，反向提醒本项目采用按事务授权，而不是默认持续查看老人位置或设备活动。

来源：[远程守护长辈](https://consumer.huawei.com/cn/support/content/zh-cn16073229/)、[关爱长辈](https://consumer.huawei.com/cn/support/content/zh-cn16094108/)

### 小米与小度

小米官方页面展示语音提醒和家庭传声；百度官方智慧养老方案把智能屏、地图和 App 作为载体。此类产品验证了语音与固定家庭终端的价值，但硬件生态会提高获客、适配和售后成本。

来源：[小米小爱智能闹钟](https://www.mi.com/mi-smartalarm)、[小爱开放平台](https://developers.xiaoai.mi.com/xiaoai6)、[百度智能云智慧养老](https://cloud.baidu.com/doc/ACSP/index.html)

### Amazon Alexa

Amazon 官方帮助列明语音呼叫、家庭消息和紧急联系人能力，也明确普通 Alexa Communication 不能直接拨打紧急号码，网络或联系方式异常会导致失败。Amazon 还在 2026 年停止 Alexa Routines Kit，提醒我们不能把核心事务状态完全绑定在单一第三方能力上。

来源：[Alexa FAQ](https://digprjsurvey.amazon.com/csad/help/node/201602230)、[Alexa Emergency Contact](https://digprjsurvey.amazon.com/csad/help/node/G6WYZPF5XKHNBZKA)、[Alexa Routines Kit](https://developer.amazon.com/en-US/alexa/alexa-routines-kit/)

## 3. 机会空白

**[分析]** 市面能力已经覆盖提醒、语音、共享和远程守护，但以下组合仍值得验证：

- 老人先看到系统理解，再决定是否创建或共享；
- 每次只共享一件事务所需字段；
- 家属接受、拒绝、建议改期和未回应都有明确状态；
- 家属的修改建议必须由老人确认后生效；
- 老人取消后，双方状态同步且不可继续处理旧请求；
- AI 失败时能降级到结构化表单，不阻断事务。

## 4. 本方案从竞品得到的具体决策

1. 采用语音 + 分字段确认，而不是只有聊天框。
2. 协作关系首次建立需要双方确认。
3. 单次请求默认不包含位置轨迹、历史日程和通讯录。
4. 家属只能回应请求，不能直接覆盖老人事务。
5. 网络、消息或 AI 不可用时显示真实失败并提供替代动作。
6. 核心业务状态保留在自身模型中，外部消息渠道只是通知适配器。
