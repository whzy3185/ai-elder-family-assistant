# 信息架构

版本：`IA_VERSION=1.0.0`

## 1. 架构原则

- 业务产品只有老人端和家属端；Demo Controller 是外层演示工具，不属于真实产品导航；
- 不设置底部多功能导航，避免制造未实现入口；
- 老人端围绕“当前事务”形成单线结构，家属端围绕“待回应请求”形成单线结构；
- 关系确认是核心授权，不由预置登录状态替代；
- 个人事务先保存，家庭共享后发生；
- 页面展示状态来自同一领域对象，不在页面内复制互相冲突的数据。

## 2. 顶层结构

```text
Demo Shell（仅演示环境）
├─ DM-01 角色切换
├─ DM-02 场景预设
├─ DM-03 固定演示时间
├─ DM-04 Reset
└─ Business App
   ├─ 老人端
   │  ├─ 家庭关系
   │  ├─ 当前事务
   │  ├─ 个人提醒
   │  └─ 当前协作请求
   └─ 家属端
      ├─ 家庭关系
      └─ 待回应请求
```

## 3. 老人端信息架构

```text
EL-TASK-00 首页
├─ 记一件事
│  └─ EL-TASK-01 输入
│     ├─ EL-TASK-02 处理中
│     ├─ EL-EX-01 缺失
│     ├─ EL-EX-02A 解析失败
│     │  └─ EL-EX-02B 手动填写
│     ├─ EL-TASK-03A 正常理解结果 ─┐
│     └─ EL-TASK-03B 识别错误结果 ─┴→ EL-TASK-04 单字段修改 / EL-TASK-05 最终确认
│           └─ EL-TASK-06 事务详情/提醒已保存
│              ├─ EL-SHARE-01 是否请求小梅
│              │  ├─ EL-SHARE-01B 只提醒自己
│              │  └─ EL-SHARE-02 共享预览
│              │     ├─ EL-SHARE-03 发送中
│              │     ├─ EL-SHARE-04A 发送成功
│              │     ├─ EL-SHARE-04B 等待回应
│              │     └─ EL-EX-03 发送失败
│              ├─ EL-TASK-08 修改事务
│              ├─ EL-EX-06A 取消事务
│              └─ EL-TASK-09A 确认完成
└─ 家庭协作
   ├─ EL-REL-01 首次介绍
   ├─ EL-REL-02 身份与权限
   ├─ EL-REL-02A 同意确认
   ├─ EL-REL-07 她能看到什么
   └─ EL-REL-04A 关系详情/结束
```

## 4. 家属端信息架构

```text
家庭关系
├─ FM-REL-01 模拟扫码/申请
├─ FM-REL-02 建立成功
├─ FM-REL-03 被拒绝
└─ FM-REL-04 已结束

FM-REQ-00 请求空状态
└─ FM-REQ-01 请求列表
   └─ FM-REQ-02 请求详情
      ├─ FM-REQ-03A/B 接受
      ├─ FM-REQ-04A/B 拒绝
      └─ FM-REQ-05A/B 建议改期

不可操作结果
├─ FM-EX-01 已撤回
├─ FM-EX-02 已取消
└─ FM-EX-03 旧请求失效
```

## 5. 领域对象与页面所有权

| 对象 | 所有者 | 老人端入口 | 家属端入口 | 关键规则 |
|---|---|---|---|---|
| `Relationship` | 双方共同关系，老人掌握当前授权确认 | `EL-REL-*` | `FM-REL-*` | 关系不自动开放事务 |
| `Task` | 张阿姨 | `EL-TASK-*` | 无直接入口 | 家属不能编辑、取消、完成 |
| `Reminder` | 张阿姨 | `EL-TASK-06/07` | 不可见 | 与协作请求独立 |
| `ConsentGrant` | 张阿姨授权 | `EL-SHARE-02` | 只看结果范围 | 每件事务单独确认 |
| `AssistanceRequest` | 张阿姨发起，双方可见 | `EL-SHARE-*`、`EL-EX-*` | `FM-REQ-*`、`FM-EX-*` | 绑定 taskVersion |
| `Response` | 小梅提交，双方可见 | `EL-SHARE-05—09` | `FM-REQ-03—05` | 不直接改变事务 |

## 6. 路由与定位约定

后续 Web 路由必须稳定支持演示和截图；具体实现可使用 query 或 path，但以下定位语义冻结：

| 页面族 | 推荐路由 |
|---|---|
| 老人首页/事务 | `/elder/task/:taskId?` |
| 老人关系 | `/elder/relationship` |
| 老人共享请求 | `/elder/request/:requestId?` |
| 家属请求列表 | `/family/requests` |
| 家属请求详情 | `/family/requests/:requestId` |
| Demo 场景入口 | `/demo?scenario=<scenarioId>&role=<role>` |

每个页面状态同时暴露稳定 `data-screen-id`，值等于页面矩阵编号，以支持测试和静态导出。

## 7. 导航限制

- 老人首页只显示“记一件事”、当前事务和家庭协作状态；
- 家属首页只显示关系和请求列表；
- 不显示历史、发现、聊天、健康、位置、支付、设置中心或管理入口；
- P1 字号/高对比只有在实际实现后才显示；
- 已完成或已取消事务只作为当前演示结果，不建设历史中心；
- 所有按钮必须在页面矩阵中有下一步，禁止空按钮。
