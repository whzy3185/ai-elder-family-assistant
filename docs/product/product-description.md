# 安心记事：产品说明

Release 1.1.0 · 2026-10-07 · 主要演示设备：390×844 移动 Web。

运行源码冻结于 `6a3734b`。最终提交 SHA 另见交付版本记录；图文与 Web 的对应关系见 `exports/source-manifest.json`。

## 1. 产品概览

帮助一位有自主决定能力的老人，把一句日常外出需求整理为可检查、可纠错的个人事务，保存提醒，再自主决定是否向女儿提出一次陪同请求。产品价值是让双方知道这件事的内容、权限、状态和下一步。

本次只演示“公交卡年审提醒及请求女儿陪同”。不提供办理政策、材料、资格或机构真实性判断；社区服务中心及家庭身份均为虚构演示数据。

## 2. 目标用户

张阿姨，72岁，具备自主决定能力，会微信语音、扫码和基本手机操作，独居或白天独处，不喜欢复杂表单和含义模糊的反馈。年龄、居住与能力条件是本项目选择的设计画像，未通过真人访谈验证，不代表所有老人。

小梅是同城成年女儿，工作繁忙，可查看具体请求但不能保证及时回复或陪同。她是受邀协助者，不能接管妈妈的事务。

## 3. 实际使用条件

设想产品由双方分别在手机上使用；本次原型通过同一浏览器的角色切换模拟双方，数据存储于该浏览器 LocalStorage，不实现真实双设备同步。评审使用现代桌面或手机浏览器，无需登录、密钥、AI额度或私人账号。

固定演示时钟为2026-10-06 20:00，时区Asia/Shanghai。“明天”固定指10月7日，不随评审电脑日期变化。示例事务09:00，提前30分钟提醒08:30；改期14:00后提醒13:30。

## 4. 老人自己的需求

张阿姨需要记住办事时间，确认系统是否理解正确，方便修正错误；她还需要决定是否告诉女儿、知道告诉了哪些内容、理解女儿是否真正答应。家属未回复、拒绝或关系未建立，均不应阻止她保存自己的提醒。

## 5. 家属的诉求

小梅需要快速看到事项、日期、时间、地点及希望陪同的意图，能明确接受、拒绝或建议改期；她不需要阅读妈妈的原话和全部日程，也不应因建立关系承担持续监控或必须回应的责任。

## 6. 当前替代方式

手机提醒工具可以保存时间和任务；聊天或电话可以询问陪同，但双方需要重新解释办事信息并核对回应。Apple共享列表偏向共同维护任务，Huawei家庭守护偏向持续关系。本方案取结构化字段和双方确认，保留老人对个人事务的所有权。

这些替代方式的比较属于继承资料与方案分析，尚未取得本目标家庭的真实替代流程观察。

## 7. 研究依据与证据等级

两份继承文字记录及官方来源见 `docs/research/evidence-index.md`、`huawei-study.md`、`apple-study.md` 和 `docs/11-sources.md`。

Huawei记录影响默认可读性、触控大小和关系双方确认；Apple记录影响字段复述、单字段修改以及任务与协作状态分离。最小共享与“家属只能建议”是本项目的产品取舍，不冒充竞品实测结果。

两次实际体验的严格证据仍为PARTIAL：缺设备型号、小版本、关键截图/录屏及可独立核验的原始体验附件。本Agent未亲自操作这两个产品。本项目没有真人访谈、用户评价、留存或增长实测；目标用户能否理解单次共享仍是假设。

## 8. 核心问题

一件事被AI整理、个人提醒保存、陪同请求发送、女儿接受和现实事务完成，是五种不同状态。若反馈把它们混为“成功”，老人可能误以为已经有人陪同，家属也可能误以为自己接手了事务。

本方案优先解决：老人先纠正理解，再控制一次有限共享，最后得到明确协作结果。

## 9. 范围与取舍

必做：关系申请与同意/拒绝/结束，输入与原话复述，时间纠错，个人提醒，单次共享预览，双端请求与回应，改期、未回应、撤回、取消、完成，失败重试，独立评审辅助恢复及全部关键画面。

实现的增强项只有字号和高对比设置。主动舍弃多家属、全量历史中心、通用聊天、定位监控、医疗诊断、应急救援、支付、政务建议、真实语音/AI/通知、账号与后台：这些会增加权限和异常组合，不能提升本次唯一事务的闭环质量。

## 10. 信息架构

老人产品默认/：事情与家人两项导航；首页提供阅读方式入口。事情完成输入、核对修改、保存详情、共享与结果；家人完成邀请、身份核对、同意/拒绝、权限与结束协作。

小梅产品/family：消息与家人。消息列表、请求详情、答复确认与结果完整可用。/review在手机画布之外提供独立评审辅助，角色切换、13种快捷情况、时钟、恢复与全部画面入口不属于双方产品导航。

## 11. 主流程

老人邀请小梅 → 小梅申请 → 老人核对身份和权限并确认同意 → 输入示例 → AI模拟把9点理解为8点 → 老人改为9点，提醒联动为8:30 → 确认保存 → 决定请小梅陪同 → 查看五项共享内容 → 确认发送 → 家属查看并确认接受 → 老人看到答应结果 → 模拟提醒 → 老人在“现实事情已办完”的确认页标记完成。

从恢复初始状态起可连续操作，主流程不需要加载中间场景。

## 12. 页面与状态

页面矩阵固定65个编号，覆盖老人端、家属端、关系授权、确认、结果及演示控制。所有编号均有实际Web画面和独立全长PNG；`exports/prototype-index.md`提供角色、状态、入口、图片、PDF页码及测试映射。

关键状态包含首次/空状态、理解错误、缺失、处理中、失败、重试、修改、发送中、等待、接受、拒绝、建议改期、撤回、取消、完成。DM-01身份、DM-02快捷情况、DM-03时间及DM-04恢复属于独立评审辅助，静态图分别截取对应工具区域，产品画面不包含它们。

## 13. 权限模型

关系同意只建立通道。每件事务另行确认共享，接收者固定小梅。仅共享事项、日期、时间、地点、希望陪同；不共享原话、个人提醒时间、其他事务、历史或位置。

老人可以纠正、保存、修改、撤回协作、取消或完成事务；家属只能回应当前有效请求。改期建议必须经老人接受。当前安排已为14:00时不提供相同时间的建议或重复修改入口；无变化不递增版本。结束关系使旧请求失效，但个人事务和提醒保留。前端角色规则用于演示，不声称具备生产环境身份认证或服务端权限防护。

## 14. 事务状态机

空 → 草稿/整理中 → 待确认 → 已保存 → 已完成或已取消。整理失败或信息缺失保留输入，可返回或手动恢复；保存前不会发请求。

规格“已保存SAVED”对应实现`CONFIRMED`。修改已保存的共享字段使版本递增，提醒随事务时间更新。完成与取消均停止个人提醒；完成只能由老人确认。

## 15. 协作状态机

未共享 → 发送中 → 等待回复 → 接受、拒绝或建议改期；等待/建议可撤回；取消事务、修改版本或结束关系使旧请求失效。

发送失败不会创建家属请求。实现以`NONE`及失败页表达尚未创建请求；超时以`NO_RESPONSE`表达仍可回应的等待状态。已发送≠答应，答应≠完成。

修改或接受改期后，旧答复不继承，新安排先保存在老人端。只有再次查看共享并确认发送，才生成绑定新版本的新请求。旧requestId的答复不能覆盖新请求。

## 16. 核心功能：纠错后保存并选择共享

用户目标：准确记好10月7日9点的事务和8:30提醒，自主决定是否请女儿陪同。

输入：当前文字、模拟语音示例，或手动填写的事项、时间和地点。输出：结构化事务、个人提醒以及经确认后生成的五字段请求。

页面行为：理解页显示时间/地点/提醒，原话可展开查看；改时间后复述最终安排；保存结果明确“还没有告诉小梅”；共享选择与预览分开，发送中不声称送达。家属回应有确认，结果回到同一事务。

规则：字段齐全且经老人确认才保存；时间与提醒相差30分钟；仅当前版本请求可回应；同一请求重复发送/接受不产生新结果。必要信息缺失、失败、放弃共享、未回应和拒绝均有可继续或结束的路径。

## 17. AI介入与纠正规则

AI仅在输入后模拟整理当前原话，不调用真实模型，不使用真实历史记忆，不查询公交卡政策或办事材料，不自主保存、联系家属或选择改期。页面展示原话作为整理依据；手动模式明确字段由用户填写。

固定示例演示9点→8点错误；老人点击改时间纠正。手动表单可编辑事项、时间与地点，日期固定10月7日，时间支持09:00/14:00。演示不保证任意自然语言、其他日期或事务类型的解析；未知内容应使用手动方式并核对全部字段。

解析失败保留原话并支持重试/手动；空输入不显示“已经听清”，不猜事项。没有虚构置信度、材料建议或“AI保证正确”的反馈。若输出不可信，返回输入或手动填写，不确认、不发送即可。

## 18. 异常处理

关系拒绝：继续个人提醒；不共享：家属列表无事务；发送失败：事务与提醒保留，重试只生成一条；发送中刷新：恢复未发送及重试页。

未回应：明确没有答应，可等待或撤回；家属拒绝：事务继续；改期：老人同意才改，拒绝保留当前时间；撤回：只终止陪同；取消：停止事务、提醒并使请求失效；修改已接受事务：旧接受失效，重新授权发送。

返回保留草稿，包括用户清空后的输入。过期解析回调不能处理新草稿。完成后可查看当前只读结果，也可开始新事；不建设历史中心。

## 19. 适老设计

默认正文20px、辅助18px、标题30px，主按钮至少56px；控件使用文字标签和12px间距，危险动作与相邻按钮至少16px。关键状态有持久标题与说明，不只依赖颜色。所有关键操作支持点击或Tab/Enter，无长按、滑动和hover依赖。

导航在文档流中，长页可滚动，不遮挡操作；危险动作先说明后果再确认；输入标签保留且逐字输入不丢焦点。支持大字及高对比，默认本身可读。60产品页标准/24px大字/200%等效缩放布局与对比检查通过，仍不能替代真人可用性测试。

## 20. 核心成功指标

无外部操作指导，正确保存指定事务、纠正一次系统错误、自主完成或拒绝单次共享，并准确解释个人事务和家属协作状态的人数 ÷ 开始完整测试且有可判定结果的目标老人人数。

放弃操作计为失败，不从分母删除；因设备故障无法判定者单独报告。每人首轮计一次，以观察与事后状态解释共同判定。观察周期为第一轮测试的一周。当前无真人实测值，不把Agent测试通过率当作该指标。

## 21. 三个过程指标

错误纠正成功率：在固定识别错误任务中，独立把8点改9点并确认8:30提醒的人数 ÷ 遇到该错误的目标老人人数；每人首轮一次，一周观察。

共享范围理解正确率：能说明家属只看到本次五项信息、看不到其他日程/原话/提醒的人数 ÷ 完成共享决策且接受理解提问的人数；无论选择共享或拒绝均纳入，逐人计一次。

主流程完成时间中位数：从开始表达到正确解释最终协作状态的分钟数中位数；只对成功完成者计算，同时报告放弃人数与帮助次数，避免只展示较快样本。均为待测指标，不填写虚构数值。

## 22. 风险指标与问题发现

逐人记录把已发送误当已答应、把答应误当事务完成、以为家属能看到全部日程的次数及涉及页面；同时记录错误时间被保存、无法返回、误取消及求助次数。

测试观察员只记录首次行为，不立即指导；危险误解发生时先停止模拟任务、澄清并保存触发路径。用屏幕操作记录与状态解释对照发现误导；任何越权或取消后仍可回应作为阻塞缺陷处理。

## 23. 最小用户验证方案

计划招募5–8组符合条件的老人及成年家属，首轮一周，每组25–40分钟。使用虚构身份和事务，告知原型不提供真实提醒/消息，不收集家庭位置、真实日程或健康信息。

老人先独立完成纠错与共享选择，家属回应，再让老人解释当前状态；另分配取消或未回应任务。观察员不讲按钮位置，任务说明不计为操作帮助；帮助、放弃与设备问题分别记录。样本只用于发现障碍，不推算全体老人表现。

若发现严重状态误解、无法纠错或错误共享，先调整对应措辞/布局/确认顺序并复测；没有严重问题且核心流程可独立完成，再考虑验证更多事务。尚未开展该真人测试。

## 25. 已知限制

研究证据PARTIAL、没有真人验证；仅支持固定模拟案例与两种时间；语音、AI、提醒、消息及身份均模拟；角色共享只在同一浏览器，跨设备/跨标签页实时协同未实现。重置会清空当前模拟状态；敏感操作不具备生产级认证。

原型初次构建需要Docker下载基础镜像；运行不调用外部服务。完整已完成/已取消结果只保留当前事务，不提供全量历史。最终平台上传、SHA确认及交卷属于独立动作，不能由本产品说明推定已经完成。

## 26. 下一步最值得验证的一件事

验证符合画像的老人能否独立理解并控制“单次共享”：知道自己选择了什么、家属看到什么，以及已发送是否意味着已答应。优先用上述最小测试定位误解，再决定是否调整共享和结果页面；不优先扩大功能范围。
