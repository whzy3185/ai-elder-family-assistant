# 产品文案规范

版本：`CONTENT_GUIDELINES_VERSION=1.0.0`

冻结日期：2026-10-06（Asia/Shanghai）

## 1. 语气

文案面对能自主决定的成年人：直接、具体、平静、尊重。系统说明自己做了什么，不替用户下结论，不制造紧迫感，也不把家属包装为管理者。

优先使用：

- 短句；
- 日常动词；
- 人名和具体对象；
- 明确时间与后果；
- “你可以……”而不是命令；
- “没有发出去”而不是技术错误码。

## 2. 固定术语

| 概念 | 界面用语 | 禁止替代 |
|---|---|---|
| 创建事务 | 记一件事 | 创建任务实例 |
| 修改字段 | 改时间 / 改地点 | 编辑时间字段 |
| 保存 | 确认记好 | 提交解析结果 |
| 请求陪同 | 请小梅陪我去 | 创建协作请求 |
| 不共享 | 只提醒我自己 | 跳过共享 |
| 发送 | 发给小梅 | 推送给协作者 |
| 未回应 | 小梅还没有回复 | 请求超时 / 默认拒绝 |
| 撤回请求 | 不用小梅陪了 | 取消协作对象 |
| 取消事务 | 取消这件事 | 删除任务 |
| 家属建议 | 小梅建议改到下午 2 点 | 家属更新任务 |
| 完成 | 这件事办完了 | resolve / close |
| 手动替代 | 手动填写 | 降级入口 |

## 3. 页面标题和按钮

- 标题说明当前要做的事，如“看看我理解得对不对”；
- 主按钮使用“动词 + 对象”，如“发给小梅”；
- 危险按钮写清结果，如“确认取消这件事”；
- 返回按钮根据语境写“返回修改”“暂不发送”，不用含义模糊的“取消”；
- 按钮不以“好的”“知道了”承担多个不同结果；
- 同一动作在老人端和家属端保持同名。

## 4. 结果反馈结构

所有成功、等待、失败和终态按三层写：

1. **发生了什么**：已经记好 / 没有发出去；
2. **当前状态**：明天 8:30 仍会提醒 / 小梅还没回复；
3. **下一步**：你可以重试 / 继续等 / 撤回请求。

示例：

> **还没有发给小梅**  
> 你的事情和明天 8:30 的提醒已经保留。  
> 你可以再试一次，或者暂不发送。

## 5. AI 与事务文案

| 页面 | 标题/主文案 | 主操作 | 必须避免 |
|---|---|---|---|
| `EL-TASK-01` | 你想记什么事？ | 模拟说话 / 手动填写 | “向 AI 下达指令” |
| `EL-TASK-02` | 正在帮你整理 | 等待 | 暗示已保存 |
| `EL-TASK-03A` | 看看我理解得对不对 | 改时间 / 确认无误 | 虚构置信度 |
| `EL-TASK-03B` | 时间可能不对，请你看一看 | 改时间 | “识别准确率低” |
| `EL-TASK-04` | 改成几点？ | 改成上午 9:00 | “编辑字段” |
| `EL-TASK-05` | 再看一遍，确认后才会记好 | 确认记好 | 未确认先执行 |
| `EL-EX-01` | 还需要知道时间 | 补上时间 | “你没说清楚” |
| `EL-EX-02A` | 这次没有整理好 | 再试一次 / 手动填写 | 错误码、责怪用户 |
| `EL-TASK-06` | 这件事已记好 | 请小梅陪同 / 只提醒我自己 | 把保存说成已共享 |

原始表达标题固定为“你刚才说”，结构化结果标题固定为“我理解的是”，确认提示固定为“请看看时间和地点对不对”。

## 6. 共享与回应文案

| 状态 | 冻结文案要点 |
|---|---|
| 只提醒自己 | “没有告诉小梅。明天 8:30 仍会提醒你。” |
| 共享预览 | “这次小梅会看到以下内容”；另列“她不会看到” |
| 发送中 | “正在发给小梅”；不得写已收到 |
| 发送成功 | “已经发给小梅” |
| 等待回应 | “小梅还没有回复。你的提醒已经设好。” |
| 已接受 | “小梅答应陪你去”；不得写事情已完成 |
| 已拒绝 | “小梅这次不能陪同。你的事情和提醒没有取消。” |
| 建议改期 | “小梅建议改到下午 2 点。只有你同意后时间才会改变。” |
| 未回应 | “小梅还没有回复”；不得解释为拒绝 |
| 撤回 | “已经告诉小梅不用陪同。你的事情和提醒还在。” |
| 取消事务 | “这件事和提醒已取消，小梅也不能再回应原请求。” |
| 旧请求失效 | “妈妈更新了这件事，请查看新请求。” |

## 7. 关系与权限文案

关系建立页必须明确写：

> 小梅只能看到你主动发给她的这件事。她不会自动看到你的其他提醒、历史事务或位置。

共享预览按两组呈现：

**小梅会看到**：事项、日期、时间、地点、希望她陪同。  
**小梅不会看到**：个人提醒时间、输入原话、AI 整理过程、其他事务、历史和位置。

不使用“授权全部”“远程守护”“管理长辈”“监护人”等超出当前关系的表述。

## 8. 时间和人物格式

- 老人端首次出现时间：`明天上午 9:00（10 月 7 日）`；
- 提醒：`明天上午 8:30 提醒你`；
- 修改时同时显示旧值和新值，不用只显示箭头；
- 家属端称“张阿姨”或“妈妈”，根据预置关系保持一致；
- 老人端称“小梅”，不使用手机号或账号代替；
- “社区服务中心”须作为演示中的虚构地点，不扩写地址或真实性承诺。

## 9. 禁用表达

- “很简单”“你又弄错了”“不会用就让孩子来”；
- “系统已智能判断”“AI 保证准确”；
- “小梅一定会来”“已送达即已同意”；
- “为了安全，默认共享位置”；
- “根据官方要求需携带……”；
- “老人无能力操作”“自动转交监护人”；
- 单独用“成功”“失败”“确定”“取消”而不说明对象和后果；
- 技术词：payload、schema、requestId、taskVersion、adapter、timeout、invalidated。

技术状态只可出现在显式标注的 Demo Controller 或测试材料中，不能出现在老人/家属业务界面。

## 10. 文案审计

`TC-CONTENT-001` 对所有页面做以下检查：

- 固定术语一致；
- 禁用表达为零；
- 结果包含发生了什么、当前状态、下一步；
- 未回应、拒绝、撤回、取消四者没有混写；
- 保存事务、发送请求、家属接受、事务完成四者没有混写；
- 权限页同时说明可见和不可见内容；
- 每个危险操作按钮写清对象；
- 文案不假装真实 AI、真实消息或真实政务服务。
