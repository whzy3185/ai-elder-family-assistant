# AI 理解规则

版本：`AI_RULES_VERSION=1.0.0`

冻结日期：2026-10-06（Asia/Shanghai）

状态：`PASS / 阶段 05 Gate`

## 1. 角色和边界

AI 只把张阿姨当前一次输入整理成“待确认草稿”。AI 不是事务所有者、家属代理、政务顾问或行为能力评估者，也不执行保存、共享、回应、改期、取消和完成。

```text
当前输入
→ 整理与字段提取
→ 张阿姨看见原话、系统理解和待确认字段
→ 张阿姨修改或确认
→ 才能保存个人事务
→ 另一次明确确认后才可共享
```

页面上的“AI”统一称为“帮你整理”，不得暗示权威判断或已经代办。

AI 只允许：

- 整理当前用户输入；
- 提取事项、日期、时间、地点和提醒方式；
- 识别是否提到希望家属陪同。

AI 不允许：

- 自动共享；
- 自动替老人邀请家属；
- 自动接受家属建议；
- 自动推断政务要求或补充材料清单；
- 自动进行医疗建议；
- 自动扩大数据访问；
- 自动判断老人行为能力。

## 2. 允许使用的信息

| 输入 | 是否允许 | 规则 |
|---|---:|---|
| 当前页面的语音转文字或手动文字 | 是 | 只处理本次明确提交的文字 |
| 当前固定演示时间 | 是 | 仅把“明天”解析为 2026-10-07 |
| 用户在本次流程中手动修正的字段 | 是 | 修正值覆盖解析值，不再被 AI 改回 |
| 当前事务已确认字段 | 是 | 只用于当前页面复述和联动提醒 |
| 其他事务、历史输入或长期记忆 | 否 | 本版不读取、不建设历史记忆 |
| 通讯录、位置、健康、设备、相册 | 否 | 未采集，也无读取入口 |
| 家属端数据和回应 | 否 | AI 不读取或替家属作答 |
| 公交卡年审政策和网络资料 | 否 | 不检索、不补充、不声称真实 |

## 3. 允许输出的字段

| 字段 | 必要性 | 固定示例 | 规则 |
|---|---|---|---|
| `title` 事项 | 必填 | 办理老年公交卡年审 | 只做简短整理，不扩写政策 |
| `date` 日期 | 必填 | 2026-10-07 | 同时显示“明天（10 月 7 日）” |
| `time` 时间 | 必填 | 主演示先为 08:00 | 必须标为待确认 |
| `location` 地点 | 必填 | 社区服务中心 | 仅记录用户说法，不验证真实地点 |
| `reminderMode` 提醒方式 | 选填 | 提前 30 分钟 | 未明确时询问或保持未设置 |
| `reminderAt` 提醒时间 | 派生 | 07:30，纠正后 08:30 | 只能由已显示的事务时间和明确偏移计算 |
| `assistanceMentioned` 协作意图 | 选填 | 希望小梅陪同 | 只识别“提到”，不创建请求 |

AI 输出不得包含模型名称、概率、内部提示、推理过程或虚构置信度。页面不得显示“准确率 98%”“高置信度”等无真实依据的信息。

## 4. 页面呈现契约

`EL-TASK-03A` 和 `EL-TASK-03B` 必须同时显示：

1. 原始表达：完整保留本次输入文字；
2. 系统理解：逐字段显示事项、日期、时间、地点、提醒和协作意图；
3. 待确认提示：明确写“请看看时间和地点对不对”；
4. 字段操作：每个可修改字段使用直白入口，如“改时间”；
5. 执行边界：未点击“确认记好”前，不创建事务和提醒；
6. 共享边界：即使输入提到小梅，也只显示协作意图，不发送请求。

正常解析结果也必须确认，不能因系统认为“正确”而跳过确认页。

## 5. 纠错规则

主演示固定产生可见错误：09:00 被整理为 08:00，对应提醒为 07:30。

```text
EL-TASK-03B 看到 08:00 / 07:30
→ EL-TASK-04 点击“改时间”
→ 选择 09:00
→ 系统机械联动提醒为 08:30
→ EL-TASK-05 重新复述完整结果
→ 张阿姨确认后保存
```

- 修改一个字段不得清空其他字段；
- 用户明确修改值优先于此前 AI 输出；
- 提醒联动属于确定性计算，不包装成 AI 建议；
- 返回上一步保留原始表达和所有已修改字段；
- 不允许用重新说整句话作为唯一纠错方式。

## 6. 信息不明确

必要字段为事项、日期、时间、地点。任一缺失时进入 `EL-EX-01`，不得猜测。

| 情况 | 页面行为 | 用户选择 | 去向 |
|---|---|---|---|
| 缺一个必要字段 | 明确指出“还需要时间”等具体字段 | 补充该字段 | `EL-EX-02B` → `EL-TASK-05` |
| 多个必要字段缺失 | 逐项列出，不一次追问抽象问题 | 手动填写 | `EL-EX-02B` |
| 相对日期无法基于固定时钟唯一确定 | 不自行选择日期 | 选择日期 | `EL-EX-02B` |
| 提醒方式未说 | 不默认“提前 30 分钟” | 不设置或手动选择 | `EL-EX-02B` |
| 未提家属 | `assistanceMentioned=false` | 保存后仍可主动选择是否邀请 | `EL-SHARE-01` |

错误提示使用“我还需要知道时间”，不得写“你没有说清楚”。

## 7. AI 失败和降级

```text
EL-TASK-01 提交输入
→ EL-TASK-02 正在整理
→ EL-EX-02A 未能整理
→ 原输入保持逐字可见
→ 选择“再试一次”或“手动填写”
→ EL-EX-02B 手动表单
→ EL-TASK-05 继续确认
```

失败时必须满足：

- 不出现“已记好”“已发送”等成功语言；
- 不清空、重写或截断原输入；
- 手动填写路径不依赖 AI 恢复；
- 重试由用户主动触发，不无限自动重试；
- 家属端不产生请求；
- 失败原因只写用户可理解的结果，不暴露堆栈、接口地址或内部错误；
- 模拟失败必须在演示工具中标明为预设场景。

## 8. 明确禁止

AI 不得：

- 自动保存事务或个人提醒；
- 自动共享、自动邀请小梅或自动重试发送；
- 自动替张阿姨接受小梅的改期建议；
- 自动推断公交卡年审资格、办理要求、材料、费用或网点真实性；
- 自动补充用户未说过的材料清单；
- 提供医疗、用药、应急或行为能力判断；
- 因“老人”身份扩大数据访问或默认家属托管；
- 从不熟悉手机推断无正常行为能力；
- 读取历史、位置、健康、通讯录或其他未授权数据；
- 把“希望小梅陪同”解释为小梅已经同意；
- 把模型输出描述为事实、官方要求或真实办理结果。
