# 事务状态机

版本：`TASK_STATE_MACHINE_VERSION=1.0.0`

冻结日期：2026-10-06（Asia/Shanghai）

## 1. 作用域

事务状态机只描述张阿姨自己的“公交卡年审”事务，不描述小梅是否收到或答应陪同。协作结果不能代替事务结果。

## 2. 状态定义

| 状态 | 含义 | 是否持久化正式事务 | 可离开方式 |
|---|---|---:|---|
| `DRAFT` | 老人正在输入，尚无可确认解析结果 | 否 | 提交解析、放弃草稿 |
| `PARSED` | 已得到结构化结果，尚未展示给老人确认 | 否 | 进入确认页 |
| `NEEDS_CONFIRMATION` | 老人正在检查或修改结构化字段 | 否 | 确认保存、继续修改、返回草稿 |
| `SAVED` | 老人已确认，个人事务与提醒已经保存 | 是 | 修改、完成、取消 |
| `COMPLETED` | 老人明确确认现实事务已办完 | 是 | 只读终态 |
| `CANCELLED` | 老人明确取消整个事务 | 是 | 只读终态 |

## 3. 解析过程状态

解析过程使用独立字段 `parseStatus`，不扩张事务业务状态：

| `parseStatus` | 含义 | 事务状态 | 用户可做什么 |
|---|---|---|---|
| `IDLE` | 尚未请求解析 | `DRAFT` | 继续输入或提交 |
| `PARSING` | 正在模拟整理 | `DRAFT` | 等待；不可提前保存 |
| `SUCCEEDED` | 已产生结构化结果 | `PARSED` | 进入确认页 |
| `MISSING_REQUIRED` | 缺少必要时间、日期、事项或地点 | `DRAFT` | 补填缺失字段 |
| `FAILED` | 无法解析 | `DRAFT` | 保留原输入、重试或手动填写 |

## 4. 完整状态转换表

| 当前状态 | 用户动作/系统事件 | 前置条件 | 新状态 | 老人看到什么 | 家属看到什么 | 后续动作 |
|---|---|---|---|---|---|---|
| `DRAFT` | 提交模拟语音或文字 | 输入非空 | `DRAFT` + `PARSING` | “正在整理你说的事情” | 无任何内容 | 等待解析结果 |
| `DRAFT` + `PARSING` | 解析成功 | fixture 匹配，产生结构化字段 | `PARSED` | 短暂处理结束 | 无任何内容 | 自动进入确认页 |
| `DRAFT` + `PARSING` | 必要信息缺失 | 至少一个必要字段为空 | `DRAFT` + `MISSING_REQUIRED` | 缺失字段及补填入口 | 无任何内容 | 补填后重新解析 |
| `DRAFT` + `PARSING` | 解析失败 | 失败场景已加载 | `DRAFT` + `FAILED` | 原输入、失败原因、重试和手动填写 | 无任何内容 | 重试或手动继续 |
| `DRAFT` | 放弃输入 | 老人确认离开 | `DRAFT`（重置） | 返回首页，无正式事务 | 无任何内容 | 可重新创建 |
| `PARSED` | 展示结构化结果 | 字段结果存在 | `NEEDS_CONFIRMATION` | 事项、日期、错误时间 8:00、地点、提醒 7:30、协作意图 | 无任何内容 | 修改或确认 |
| `NEEDS_CONFIRMATION` | 修改时间 8:00→9:00 | 输入是合法时间 | `NEEDS_CONFIRMATION` | 时间变为 9:00，提醒联动为 8:30，再次复述 | 无任何内容 | 继续检查或确认 |
| `NEEDS_CONFIRMATION` | 修改其他字段 | 新值通过字段校验 | `NEEDS_CONFIRMATION` | 只更新对应字段并再次复述 | 无任何内容 | 继续检查或确认 |
| `NEEDS_CONFIRMATION` | 返回输入 | 保留现有字段 | `DRAFT` | 原输入与修改结果仍在 | 无任何内容 | 重新表达或手动改 |
| `NEEDS_CONFIRMATION` | 确认保存 | 必要字段齐全、老人主动确认 | `SAVED` | “这件事已记好；10 月 7 日 8:30 提醒你” | 无任何内容 | 只提醒自己或决定请求小梅 |
| `SAVED` | 修改未共享字段 | 老人确认修改 | `SAVED`，`taskVersion+1` | 更新后的事务详情 | 若已有请求，只看到其授权字段；未授权字段不可见 | 返回详情 |
| `SAVED` | 修改已共享的时间、地点或请求内容 | 当前存在非 `INVALIDATED` 请求；老人确认修改 | `SAVED`，`taskVersion+1` | 新版本事务；明确旧请求已作废，询问是否重新发送 | 旧请求显示“妈妈更新了事情，此请求已失效” | 如仍需协作，创建新请求 |
| `SAVED` | 确认现实事务办完 | 仅老人可操作；事务未取消 | `COMPLETED` | “这件事已完成”；不再触发提醒 | 只能看到此前已授权请求的结果，不可替老人完成 | 只读查看 |
| `SAVED` | 取消整个事务 | 老人二次确认 | `CANCELLED` | “事务和提醒已取消”；说明协作请求同步失效 | 已存在请求显示“妈妈已取消这件事”，不可回应 | 只读查看 |
| `COMPLETED` | 尝试修改、取消或再次完成 | 终态 | `COMPLETED` | 说明事情已完成，不能重复操作 | 不产生新变化 | 返回详情 |
| `CANCELLED` | 尝试修改、完成或触发提醒 | 终态 | `CANCELLED` | 说明事情已取消 | 不产生新变化 | 返回详情 |

## 5. 提醒规则

| 事务状态 | 提醒状态 | 规则 |
|---|---|---|
| `DRAFT/PARSED/NEEDS_CONFIRMATION` | 不存在 | 未保存前不创建提醒 |
| `SAVED` 且当前时间早于 08:30 | `SCHEDULED` | 等待固定演示时钟到达 |
| `SAVED` 且当前时间达到 08:30 | `TRIGGERED` | 展示“今天 9:00 办理公交卡年审” |
| `COMPLETED` | `SUPPRESSED` | 已完成不再提醒 |
| `CANCELLED` | `CANCELLED` | 取消事务同步取消提醒 |

协作请求被拒绝、未回应、发送失败或由老人撤回时，事务仍为 `SAVED`，个人提醒继续存在。

## 6. 版本规则

- `taskVersion` 从 `1` 开始；
- 修改事项、日期、时间、地点或协作请求内容时版本递增；
- 修改纯本地显示偏好不增加事务版本；
- 每个协作请求记录创建时的 `taskVersion`；
- 请求回应时必须满足 `request.taskVersion === task.taskVersion`；
- 不相等时拒绝操作并显示旧请求已失效；
- 旧请求的 `ACCEPTED` 不得复制到新版本。

## 7. 不变量

1. `SAVED` 之前不存在正式个人提醒；
2. `SAVED` 不代表请求已发送；
3. 协作请求 `ACCEPTED` 不会把事务改为 `COMPLETED`；
4. 只有张阿姨能把事务变为 `COMPLETED` 或 `CANCELLED`；
5. `CANCELLED` 后提醒不得触发；
6. 修改共享字段必须增加版本并使旧请求失效；
7. 家属操作不能直接改变事务字段或状态。
