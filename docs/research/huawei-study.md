# 体验记录 01：华为「长辈关怀 + 远程守护」

体验日期：2026-10-06

体验对象：使用华为手机的老人及其成年子女

参考版本：HarmonyOS 4.x 长辈关怀、HarmonyOS 6.x 远程守护流程

证据状态：`C-PARTIAL`，详见 [证据索引](evidence-index.md)

## 1. 体验任务

一方面调整手机，使老人更容易阅读和点击；另一方面建立老人和女儿之间的家庭协助关系，观察双方如何建立关系、完成授权，以及家属获得什么权限。

## 2. 长辈关怀

### 2.1 开启与显示调整

**[候选人观察]** 记录中的操作路径为：

> 设置 → 辅助功能 → 长辈关怀 → 开启长辈关怀

开启后可继续调整“放大显示”。候选人的直接感受是：产品没有把老人等同于“必须使用最大字体”，而是允许使用者选择适合自己的显示档位。

**[官方事实]** 华为官方说明包含放大显示，以及字体、桌面图标等显示能力；具体可用项会因设备和系统版本而异。

**[方案推演]** 当前项目的目标老人会使用微信语音、扫码和基础手机功能，因此采用“正常产品结构 + 更大的默认字号和点击区 + 简单可调文字尺寸”，而不是极端简化、不可调整的独立老人系统。

### 2.2 触控适配

**[候选人观察]** 部分参考版本提供触控时长调整，用于降低“本想点击却被识别成长按”的问题。这使适老问题从“看不清”扩展到“点不准、动作较慢、不理解复杂手势、不知道是否操作成功”。

**[方案推演]** 本项目应采用大按钮、足够间距、清晰按下反馈和结果反馈，避免把长按、精细滑动或只有图标的入口作为关键操作。

## 3. 远程守护关系建立

### 3.1 文字记录中的流程

**[候选人观察]** 记录中的双方路径为：

- 老人端：设置 → 健康使用设备 → 被家人守护 → 打开二维码；
- 家属端：设置 → 健康使用设备 → 守护家人 → 去守护 → 扫码添加。

扫码后，家属先发送申请，老人设备收到请求并明确同意后才建立关系。其业务顺序是：

> 老人提供二维码 → 家属扫码 → 家属发申请 → 老人确认 → 建立关系

**[官方事实]** 华为官方远程守护资料描述了申请、同意和关系建立等步骤，也描述了位置等持续守护能力。

**[待验证假设]** 当前没有截图、录屏和设备小版本，菜单名称、位置及能力差异仍需在最终演示材料中避免写成所有华为设备统一不变的事实。

### 3.2 对本项目的意义

**[方案推演]** 借鉴的是“双边确认”，不是持续守护的权限模型。家庭关系不能因为对方声称是子女就默认成立；家属知道自己在协助谁，老人也明确知道谁在请求建立关系。

本项目采用两层授权：

1. **关系授权**：老人同意与小梅建立家庭协作通道；
2. **单次事务授权**：老人决定是否把公交卡年审的必要字段发给小梅。

关系建立后，小梅仍不会自动看到老人的其他提醒、历史事务、位置或完整对话。

## 4. 映射到张阿姨场景

### 4.1 首次建立关系

**[方案推演]** 老人端应明确显示：

> 小梅想和你建立家庭协作。建立后，小梅可以接收你主动发给她的事情；她不会自动看到你的其他提醒、历史事务或位置。

主要操作为：

- 同意建立；
- 暂不同意；
- 她能看到什么。

### 4.2 每件事务单独共享

张阿姨保存“明天上午 9:00 去社区服务中心办理公交卡年审”后，系统另行询问是否请小梅陪同。发送前再次展示本次共享的最小字段：

- 事项：公交卡年审；
- 日期与时间：明天 9:00；
- 地点：社区服务中心；
- 所需帮助：希望小梅陪同。

只有张阿姨点击“发给小梅”，协作请求才进入已发送状态。

## 5. 采用与排除

| 华为体验观察 | 本项目采用方式 | 原因 |
|---|---|---|
| 显示尺寸可调整 | 默认大字号，并提供简单文字尺寸调整 | 尊重能力差异 |
| 关注触控时长和误操作 | 大按钮、清晰间距、避免长按关键操作 | 降低操作精度要求 |
| 二维码建立守护关系 | 首次家庭协作模拟扫码 | 减少账号输入 |
| 扫码后仍需老人确认 | 家庭关系必须双边确认 | 保留老人决定权 |
| 长期守护关系 | 关系授权之外增加单次事务授权 | 控制权限范围 |
| 可持续查看位置 | 明确不采集、不共享位置 | 当前事务不需要 |
| 关系建立后持续守护 | 每件事务仍由老人确认是否共享 | 防止关系授权扩大为数据授权 |

本项目不采用实时定位、持续监控、关系绑定后自动查看事务，也不采用“家属默认接管老人”的产品模型。目标用户具备自主决策能力，家属是协助者而不是管理者。

## 6. 研究结论

华为体验带来的两个核心原则是：

1. 系统应适应老人的显示、触控和反馈需求，而不是只把字号放大；
2. 家属参与必须经过清晰的关系确认，但长期关系不等于默认开放全部数据。

由此确定当前项目的权限原则：

> 一次建立家庭协作关系，每件事务单独确认共享。
