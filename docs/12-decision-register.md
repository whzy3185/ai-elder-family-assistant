# 研究决策登记

## 已确定决策

| ID | 决策 | 依据 | 影响 |
|---|---|---|---|
| D-001 | 只做“公交卡年审提醒 + 请求小梅陪同”这一件日常外出事务 | 48 小时范围与页面完整性要求 | 不扩展为综合养老平台或第二事务 |
| D-002 | 老人拥有事务和共享的最终确认权 | 自主权、隐私最小化、家庭权力边界 | 家属只能回应或提出修改建议 |
| D-003 | AI 仅做结构化理解 | 错误可控、考核不要求真实 AI | 先确认再执行，失败回退表单 |
| D-004 | 事务和协作请求分开建模 | 取消、未回应和建议改期需要独立状态 | 使用两个状态机而非布尔值 |
| D-005 | 原型为离线静态 SPA | Docker 演示不需要后端 | 无真实接口、密钥和外部依赖 |
| D-006 | 使用演示工具切换角色 | 评审需要连续操作双方界面 | 控制栏明确标注，不伪装成真实功能 |
| D-007 | 单次最小共享 | 避免默认开放全部日程或位置 | 每次展示共享字段并允许取消 |
| D-008 | 当前不做医疗和应急 | 专业责任和异常成本过高 | 文案和导航不得暗示相关能力 |
| D-009 | 当前只实现自主模式 | 核心用户具备自主决策能力 | 不纳入法定监护、代理核验或全权托管 |
| D-010 | 固定演示时钟为 2026-10-06 20:00（Asia/Shanghai） | 避免依赖评审打开日期 | 事务固定为 2026-10-07 09:00，提醒为 08:30 |
| D-011 | 阶段 07 起按任务链实现 Web，阶段 11 起完成 Docker | 用户要求从 阶段 00 起继续完整任务链 | 旧“全程不编码”只作为历史阶段约束 |
| D-012 | P1 仅含显示切换和可选回应说明 | P0 完整性优先 | P1 可整体删除且不得产生空入口 |

## 决策变更规则

- 新证据可以推翻设计，但必须记录原因和受影响页面；
- 不因单个便利样本扩展为人群结论；
- 改动状态规则时同步修改产品文档、页面清单、Web 原型和测试；
- 任何新增功能都必须说明替代了什么或为何值得增加页面与异常成本；
- 安全、知情同意和老人最终确认权不得为演示便利而弱化。
